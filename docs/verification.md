# 验证记录

日期：2026-09-06。版本：`0.1.0-preview`。开发主机为 macOS arm64，Go `1.27.1`。以下是实际执行结果，不是对未来平台兼容性的保证。

## 已通过

- `go test ./...`：配置、鉴权、路径与素材校验、私有文件、Cookie 编解码、MCP/REST 单元测试。
- `DY_BROWSER_TESTS=1 go test -race ./... -count=1`：包括真实 Chrome 驱动的本地模拟页面测试，未报告数据竞态。
- 本地浏览器：视频与多图上传输入、标题与富文本正文填写；准备不点击发布；明确确认后仅提交一次；重启后的相同提交返回已保存回执。
- 防误发：预览后修改文案、页面素材或会话会被拒绝；页面没有成功反馈时返回 unknown，重复确认不会再次点击。
- 登录存储：合成 Cookie 保存、恢复、删除，销毁浏览器上下文后 Cookie 与 localStorage 不再存在；QR 返回的是可解码 PNG。
- MCP：`2026-07-28` 的 `server/discover`、`2025-11-25` 的旧初始化、只注册 5 个工具、二维码二进制没有双重 Base64、未知短信参数被拒绝。
- HTTP：未授权的所有业务路由被拒绝；Host/Origin、跨站请求与 Content-Type 校验；JSON 不接受额外功能字段。
- 可执行文件启动检查：`/health` 返回 200，未授权登录接口返回 401，授权工具发现返回 5 个工具，自动 token 文件权限为 0600；没有启动或使用真实账号。
- `go vet ./...`、`go mod verify`、`git diff --check`。
- `govulncheck ./...`：当时使用的 Go 漏洞数据库未发现漏洞；这不排除未知漏洞或浏览器、操作系统层面的风险。
- macOS arm64 构建；`CGO_ENABLED=0` 下 Linux amd64 与 arm64 交叉编译。交叉编译成功不代表对应平台浏览器流程已经运行验证。

## 依赖兼容性

直接依赖已更新至核对时最新稳定发布版。实际尝试较新传递依赖时发现：

- `fetchup v0.5.3` 改变 `New` 签名，当前 rod 无法编译，保留 `v0.2.3`。
- `got v0.43.0` 移除 rod 使用的 `lib/lcs`，保留 `v0.41.0`。

浏览器必须显式使用系统已安装的可执行文件，不调用 fetchup 自动下载，也不启用 leakless 辅助二进制。模块仍在依赖图中，许可证仍需保留。

## 尚未完成的验收

匿名真实页面验证：通过现有本地代理访问抖音创作者中心，成功获取登录二维码 PNG（约 7 秒）。针对其哈希类名组件，增加了受限的相邻扫码说明匹配；不会选取首页的装饰画布。未扫码、未绑定账号、未发布作品。直连曾超时，网络条件仍影响可用性。

- 真实账号扫码后登录状态判断、退出/重启后平台接受恢复凭证。
- 真实账号的视频及图文完整发布、平台处理失败、审核状态与真实作品 ID/链接。
- 不同账号权限、页面实验版本、操作系统和浏览器版本的兼容性。
- Docker 镜像构建、容器沙箱、挂载权限和容器内浏览器流程；当前开发环境没有 Docker。

所有本地流程测试由合成素材和合成会话完成，没有发送真实作品，也没有把个人 Cookie 或素材纳入仓库。不能据此写成“已经保证真实发布成功”。首次验收应使用账号所有者确认的素材，在有界面的专用浏览器中核对；未经内容确认不应代发测试作品。
